# Яндекс Диск и CI

Удалённое хранилище DVC: `webdavs://webdav.yandex.ru/DevOps_Project_DVC`.
Локальные данные доступа находятся в `.dvc/config.local`, исключённом из Git
и Docker-контекста. Не копируйте этот файл в репозиторий.

В GitHub откройте Settings → Secrets and variables → Actions и создайте
два Repository secrets:

| Название | Значение |
| --- | --- |
| `DVC_YANDEX_USER` | Логин аккаунта Яндекс ID |
| `DVC_YANDEX_PASSWORD` | Пароль приложения «Файлы WebDAV» |

Можно создать отдельный пароль приложения для GitHub Actions, чтобы отзывать
его независимо от локального доступа. Он не становится паролем только для
чтения и не ограничивается одной папкой Диска.

CI скачивает `models` по `dvc.lock` перед тестами и сборкой Docker, затем
проверяет manifest и контрольные суммы моделей. Временный файл доступа
удаляется после шага скачивания, в том числе при ошибке. Обучение в CI не
запускается. Для pull request из стороннего fork этот job пропускается:
закрытые артефакты требуют secrets, которые таким запускам не предоставляются.

После обучения нового выпуска сначала загрузите артефакты через `dvc push`,
а затем публикуйте соответствующие изменения Git и `dvc.lock`. Код обучения
может отличаться от кода старого выпуска: его точная копия хранится внутри
выпуска. Не обновляйте lock старого обучения так, будто оно выполнено новым кодом.

Настройка workflow сама по себе не подтверждает успешный запуск GitHub Actions.
Для проверки необходимы сохранённые secrets и публикация изменений в GitHub.
